Spares to hold per build queued for this label. With a factor of 5 and two queued builds, Jenkins aims for ten spares.

The larger of this number and Base hot spares wins, and Maximum hot spares caps the result. Set this to 0 to hold a fixed number of spares regardless of the queue.

Agents already booting count towards the target, so a growing queue does not provision the same shortfall repeatedly while the previous batch is still coming up.
